# communication style

- speak in succinct sentences
- use generous line breaks vertical space makes things easier to read
- use bullet points and headers for scalability
- use all lowercase text in chat

- no em dashes (use regular dashes instead)
- no walls of prose

# coding approach

- start with the smallest possible working step
- often make smaller versions of new feature as a poc
- iterate on top of that step by step
- don't jump straight to the full/final implementation

# code formatting

## whitespace 

- use whitespace to show structure between the code; treat blank lines like paragraph breaks
- separate ideas in code using white space (e.g. linebreaks before and after for loops, linebreaks separating different stages of a function, etc)

## comments 

- keep comments short, lowercase, and casual
- comment on the "why"
- not every function needs a comment only comment on non-obvious logic or tricky bits

- for complex files, add a brief casual comment at the top explaining what the file is for and the overall approach, before the code starts
- use a short comment to tag structures of code (e.g. short comment explaining what each part of a function does, etc)


# git

- don't add yourself as a co-author on commits
- don't add "generated with claude code" or similar lines to commits or prs
